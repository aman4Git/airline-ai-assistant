# Airline AI Assistant (FlightAI)

A conversational airline assistant that searches flights and makes bookings through LLM tool calling. Every reply is also spoken aloud, and searching for a destination generates a pop-art image of that city. It uses Google Gemini (chat, image generation and text-to-speech), a local SQLite database seeded with sample flight data, and a Gradio UI.

The project is two Jupyter notebooks:

| Notebook | Purpose |
|---|---|
| [01_database_setup.ipynb](01_database_setup.ipynb) | Creates `airline.db` and seeds it with airports and 8 days of flights |
| [02_airline_assistant.ipynb](02_airline_assistant.ipynb) | Defines the tools, the image and voice helpers, the chat loop and the Gradio interface |

## Features

- **Flight search** by city name or airport code, date, time of day (morning, afternoon, evening, night) and sort order (price, departure, duration)
- **Flight booking** with a PNR and ticket number, seat inventory updated atomically
- **Natural language dates**: "tomorrow" or "next Friday" are converted to `YYYY-MM-DD` using today's date
- **Guarded booking flow**: the model must collect name and email, show a price summary and get an explicit "yes" before booking
- **Grounded answers**: the system prompt tells the model never to invent flights, prices or PNRs
- **Tool-call loop**: the model keeps calling tools until it returns a final answer
- **Destination image**: after a `search_flights` call, `artist()` generates a 1024x1024 pop-art image of the destination city and shows it beside the chat
- **Voice replies**: `talker()` turns every assistant reply into speech, which plays automatically
- **Login screen**: the Gradio app is protected by a username and password

## Getting started

### 1. Prerequisites

- Python 3.12 or newer
- [uv](https://docs.astral.sh/uv/getting-started/installation/)
- A Gemini API key from [Google AI Studio](https://aistudio.google.com/apikey)
- **Billing enabled** on that key's Google Cloud project. The free tier has a quota of zero for Gemini image models, so image generation fails without billing. Chat and text-to-speech work on the free tier.

### 2. Install dependencies

```bash
uv sync
```

This creates `.venv` and installs `gradio`, `openai`, `google-genai`, `pillow`, `python-dotenv` and the `ipykernel` dev dependency.

### 3. Configure environment variables

```bash
cp .env.example .env
```

Then set your key in `.env`:

```env
GEMINI_API_KEY=<YOUR_GEMINI_API_KEY>
```

`.env` is git-ignored. Never commit real keys. `.env.example` also lists base URLs for other OpenAI-compatible providers (Anthropic, DeepSeek, Grok, Groq, OpenRouter, Ollama) for anyone who wants to swap the model.

### 4. Create the database

Open `01_database_setup.ipynb`, select the `.venv` kernel and run all cells. Expected output:

```
Seeded 576 flights
```

### 5. Run the assistant

Open `02_airline_assistant.ipynb` and run all cells. The last cell launches Gradio, usually at http://127.0.0.1:7860. It does not open a browser automatically (`inbrowser=False`), so open the URL yourself.

Sign in with the credentials set in the `ui.launch(auth=...)` call in the last cell. The notebook currently uses a placeholder login of `admin` / `admin`. Change it before sharing the app with anyone.

Allow audio autoplay for the site if your browser blocks it, otherwise you have to press play on each reply.

## Sample data

Notebook 01 seeds data relative to **today's date**, using `random.seed(42)` so the run is reproducible.

**Airports**

| Code | City |
|---|---|
| DEL | Delhi |
| BOM | Mumbai |
| BLR | Bengaluru |
| HYD | Hyderabad |
| MAA | Chennai |
| CCU | Kolkata |
| GOI | Goa |

**Routes** (both directions): DEL-BOM, DEL-BLR, BOM-BLR, DEL-GOI, BOM-HYD, DEL-CCU

**Flights**

- 6 departures per day per direction: 06:00, 08:30, 11:15, 14:45, 18:30, 21:50
- Generated for today plus the next 7 days
- Prices in INR, randomized between 80% and 140% of the route base price
- Duration varies by -10 to +20 minutes from the route base
- 0 to 40 seats available per flight
- Flight IDs look like `FA101-20261024` (flight number + date)

> Chennai (MAA) exists as an airport but has no routes yet, so searches to or from it return no flights.

## Database schema

| Table | Columns |
|---|---|
| `airports` | `code` (PK), `city` |
| `flights` | `flight_id` (PK), `flight_no`, `origin`, `destination`, `departure`, `arrival`, `duration_min`, `price`, `seats_available` |
| `bookings` | `pnr` (PK), `flight_id`, `passenger_name`, `passenger_email`, `seats`, `total_price`, `status`, `ticket_no`, `created_at` |
| `support_tickets` | `ticket_id` (PK), `pnr`, `category`, `description`, `status`, `created_at` |

## How it works

```
User message
    │
    ▼
chat(history)  ──►  Gemini (system prompt + history + tools)
                        │
                        └── while finish_reason == "tool_calls":
                               handle_tool_calls_and_return_cities()
                                   │
                                   ├── search_flights()  ─┐  (destination city recorded)
                                   └── create_booking() ──┤──► SQLite
                                                          │
                               tool results appended ◄────┘
                               and Gemini is called again
                        │
                        ▼
                  final text reply
                        │
                        ├── talker(reply)     ──► Gemini TTS ──► output.wav ──► Audio player
                        └── artist(cities[0]) ──► Gemini image ──────────────► Image panel
                            (only if a search happened in the last tool round)
```

`chat()` returns `(history, voice, image)`, which Gradio sends to the chat, audio and image components. The text, audio and image all appear together once every step has finished.

### Image and voice helpers

| Function | Model | Output |
|---|---|---|
| `artist(city)` | `gemini-2.5-flash-image` through the OpenAI-compatible `images.generate` endpoint | A 1024x1024 PIL image in a pop-art style showing the city's tourist spots |
| `talker(message)` | `gemini-2.5-flash-preview-tts`, voice `Kore`, through the `google-genai` SDK | Gemini returns raw PCM audio (24 kHz, 16-bit, mono), which is wrapped as `output.wav` |

> Newer TTS models such as `gemini-3.8-flash-tts` return a complete WAV file rather than raw PCM. If you switch `talker()` to one of them, write the bytes straight to disk instead of wrapping them with `wave`, or the audio will be corrupted.

### Tools

| Tool | Required args | Optional args | Behavior |
|---|---|---|---|
| `search_flights` | `origin`, `destination`, `date` | `time_of_day`, `sort_by`, `max_results` (default 5) | Resolves city or code, filters by date and time window, returns only flights with seats available |
| `create_booking` | `flight_id`, `passenger_name`, `passenger_email` | `seats` (default 1) | Validates 1 to 9 seats and email format, decrements seats only if enough remain, inserts a `CONFIRMED` booking, returns PNR, ticket number and total price |

Tool errors (bad arguments, unknown tool, exceptions) are caught and returned to the model as `{"error": ...}` so it can recover instead of crashing the chat.

### Time-of-day windows

| Value | Departure window |
|---|---|
| `morning` | 05:00 to 12:00 |
| `afternoon` | 12:00 to 17:00 |
| `evening` | 17:00 to 21:00 |
| `night` | 21:00 to 23:59 |
| `any` | whole day |

## Known limitations

- **Flight data goes stale.** Flights only cover 8 days from the day notebook 01 was run. Re-run it to refresh dates. Re-running clears and regenerates `flights` (resetting seat counts) but keeps existing `bookings`, which may then point to flight IDs that no longer exist.
- **Partially implemented features.** The system prompt mentions booking lookup, cancellation, policy questions (for example baggage) and support tickets, but only `search_flights` and `create_booking` are wired up as tools. The `support_tickets` table exists but nothing writes to it yet. Questions on those topics will not be answered from real data.
- **Single currency and region.** All prices are INR and all airports are in India.
- **Demo-grade validation.** Email validation only checks for `@`. Apart from the single shared Gradio login, there are no user accounts, payment or real ticketing.
- **Local only.** SQLite plus a notebook-launched Gradio app is suitable for development and demos, not multi-user production use.
- **Slow replies.** Text, speech and image are generated one after another, so nothing appears until all three finish. One test search with an image took about 29 seconds.
- **Image cost.** A new image is generated, and billed, for every search, even for a city that was shown before.
- **Shared audio file.** Every reply overwrites `output.wav`, so two users at the same time can hear each other's audio.
- **No tool-round cap.** The tool loop runs until the model stops calling tools, with no maximum number of rounds.
- **Hardcoded login.** The `admin` / `admin` credentials live in the notebook instead of `.env`.
- **No error handling for image and voice.** If the image or TTS call fails (for example a quota error), the whole reply fails and nothing is shown in the chat.

## Troubleshooting

| Problem | Fix |
|---|---|
| `Gemini API Key not set` | Check that `.env` exists in the project root and `GEMINI_API_KEY` has a value |
| `no such table: flights` | Run `01_database_setup.ipynb` first |
| Searches return "No flights found" | The date is outside the seeded 8-day window, or the route is not served. Re-run notebook 01 |
| `Unknown city` error | Use one of the airports listed above, by city name or code |
| Notebook kernel missing packages | Select the `.venv` interpreter as the kernel, or run `uv sync` again |
| `429 RESOURCE_EXHAUSTED` when generating an image | Your key is on the free tier, which has no image quota. Enable billing on the Google Cloud project for the key |
| `Chatbot.__init__() got an unexpected keyword argument 'type'` | Gradio 6 removed `type="messages"` from `gr.Chatbot`. Remove the argument |
| No sound plays | Your browser blocked autoplay. Allow autoplay for the site, or press play on the audio player |
| Notebook changes don't appear in VS Code | The editor is showing an older copy. Run **File: Revert File**, or close the tab without saving and reopen it |
